# MobiTed

MobiTed is a Bulgarian marketplace for car and vehicle classifieds: cars, SUVs, vans, trucks, motorcycles, caravans, campers, agricultural and construction machinery, trailers, parts, tyres and wheels. The interface is in Bulgarian and every price is in EUR.

It is a full product, not a mockup. Accounts, listings, images, search, favorites, saved searches, dealers, messaging, moderation and admin all keep their data in PostgreSQL. Paid promotions use a built-in **demo** payment provider. It needs no keys and never contacts a payment network.

## Stack

- Next.js 16 (App Router, Server Components, Server Actions), React 19, TypeScript in strict mode
- PostgreSQL 16 with Drizzle ORM and SQL migrations
- Better Auth: email and password, email verification, password reset, sessions stored in the database
- Tailwind CSS 4 with design tokens in `src/styles/globals.css`
- React Hook Form and Zod, with the same schemas validating on the client and the server
- Vercel Blob for images, `sharp` for validation and resizing
- Postgres full-text and trigram search
- Vitest for unit and integration tests, Playwright for end-to-end tests

See [docs/architecture.md](docs/architecture.md) for the design decisions.

## Requirements

- Node.js 20.9 or newer (22 recommended)
- pnpm 10 (`corepack enable`)
- PostgreSQL 14 or newer with the `pg_trgm` extension. Docker Compose is provided.

## Getting started

```bash
git clone <repository> mobited && cd mobited
pnpm install
cp .env.example .env            # set AUTH_SECRET; DATABASE_URL already matches Docker Compose
docker compose up -d postgres   # or point DATABASE_URL at your own PostgreSQL
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Open http://localhost:3000.

### Development accounts

`pnpm db:seed` creates these accounts. They are for development only and the password for all of them is `MobiTed123!`.

| Email | Role |
| --- | --- |
| `superadmin@mobited.local` | Super admin (all settings) |
| `admin@mobited.local` | Admin |
| `moderator@mobited.local` | Moderator |
| `dealer@mobited.local` | Dealer, owner of "Авто Сердика" |
| `user@mobited.local` | Private user |

The seed also adds about 800 listings, 8 dealers, around 100 private sellers, favorites, conversations, reports and demo payments. It uses a fixed random seed, so every run produces the same content, but database ids change on every run: restart a running app server after reseeding. Seed listings use illustrated placeholder photos, which are generated by `/media/demo/*`.

### Emails in development

If `RESEND_API_KEY` is not set, emails are not sent. Instead, each email is printed to the server log and saved to a development mailbox at http://localhost:3000/dev/poshta. Registration works the same way: open the mailbox and click the verification link. The mailbox is turned off in production.

### Images in development

If `BLOB_READ_WRITE_TOKEN` is not set, development uploads are saved to `./.uploads` and served from `/media/uploads/*`. Production always uses Vercel Blob.

## Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | yes | PostgreSQL connection string. On Neon or Supabase, use the pooled connection string. |
| `AUTH_SECRET` | yes in production | Secret for sessions and tokens (`openssl rand -base64 32`) |
| `BLOB_READ_WRITE_TOKEN` | yes in production | Vercel Blob token for image uploads |
| `APP_URL` | no | Public base URL. On Vercel it is taken from the deployment URL. |
| `RESEND_API_KEY`, `EMAIL_FROM` | no | Email delivery. Without them, emails are logged and stored in the dev mailbox. |
| `CRON_SECRET` | recommended in production | Protects `/api/cron/maintenance` |
| `MOBITED_SKIP_EMAIL_VERIFICATION` | no | `1` turns off email verification while no email provider is configured. New accounts are created as verified. |

Payments need no environment variables.

## Scripts

| Command | Description |
| --- | --- |
| `pnpm dev` | Development server |
| `pnpm build` / `pnpm start` | Production build and server |
| `pnpm lint` | ESLint and the long-dash check |
| `pnpm typecheck` | TypeScript |
| `pnpm test` | Vitest unit and integration tests. Uses the `mobited_test` database, created automatically. |
| `pnpm test:e2e` | Playwright end-to-end tests. Builds the app and uses a freshly seeded `mobited_e2e` database. |
| `pnpm db:generate` | Generate a migration after changing `src/db/schema` |
| `pnpm db:migrate` | Apply migrations |
| `pnpm db:setup` | Apply migrations and fill empty reference tables (regions, categories, makes). Production-safe; Vercel runs it on every build. |
| `pnpm db:seed` | Replace all data with the demo dataset. Refuses to run with `NODE_ENV=production`. |
| `pnpm db:reset` | Drop all tables, then migrate and seed |
| `pnpm db:studio` | Drizzle Studio |

### Tests

```bash
pnpm test        # unit + integration (needs PostgreSQL reachable with the DATABASE_URL credentials)
pnpm test:e2e    # end-to-end
```

Both suites connect as the `mobited` user and need permission to create databases, which the Docker Compose user has. To use other databases, set `TEST_DATABASE_URL` or `E2E_DATABASE_URL`. To run E2E against a server that is already running, set `E2E_BASE_URL=http://localhost:3000`; this uses the data that server already has. If Playwright's bundled Chromium is not installed, run `pnpm exec playwright install chromium` or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.
